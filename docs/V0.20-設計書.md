## 3. DSH 插件發布

三種裝法（DSH 的 `dsh plugin` 是轉給 pnpm 的）：

```sh
# A. Release 的 tarball（不用 npm 帳號、不用建置授權）
dsh plugin --profile web add ./dsh-whale-valley-0.20.0.tgz
# B. 直接從 GitHub（lib/ 已提交，沒有 prepare 腳本，pnpm 10 不會要求授權）
dsh plugin --profile web add github:long432120-blip/dsh-whale-valley
# C. 本機開發
dsh plugin --profile web add link:/path/to/dsh-whale-valley
```

`package.json`：

- `files`: `lib`、`packs`（排除 `assets/source`）、`cordis.patch.yml`、`README.md`、`LICENSE`
- `keywords` 有 `dsh-plugin`；GitHub repo 也加上 `dsh-plugin` 話題（社群用這個話題找插件）
- `repository`、`homepage`、`bugs` 指向 GitHub

打包：`npm run build && npm pack` → `dsh-whale-valley-0.20.0.tgz`

## 4. 單機版的 AI 對話：玩家自己的 DeepSeek API Key

DSH 版的 Key 在 host（插件設定／`.env`），瀏覽器碰不到。單機版沒有 host，所以讓玩家**自己填 Key**，存在自己的瀏覽器。

### 4.1 安全

- 程式碼、角色包、打包出來的 html **沒有任何 Key**（`test/ai-browser.test.ts` 會掃 `sk-…`；發布前也掃了 `lib/`、`pixel-standalone.html`）。
- Key 存在 `localStorage['whale-pet:deepseek-api-key']`：只在這台電腦的這個瀏覽器，**只會**放在送往 `https://api.deepseek.com` 的 `Authorization` 標頭。
- 不寫進存檔、禮物碼、log、錯誤訊息；畫面只顯示 `sk-…尾碼4碼`；「測試連線」失敗只說狀態碼的意思，不顯示伺服器原文。
- 設定畫面寫明：公用電腦不要填、可以隨時清除、費用從自己的帳戶扣。
- 跨網域：DeepSeek 的 API 有開 CORS（`Access-Control-Allow-Origin: *`），雙擊開的 html（`file://`）也能直接呼叫；萬一被擋，就是走降級。

### 4.2 架構（跟 host 共用同一份邏輯）

```
點她 ─▶ pixel-stage.aiSay()                         ← 頭上冒「思考中 ●●●」
          └▶ bridge.chat(req + 遊戲狀態快照)
               ├ DSH：DshBridge → host WhaleAi（Key 在 host）
               └ 單機：LocalBridge → AIChatService（Key 在 localStorage）
                          └▶ WhaleAi（shared/ai-service.ts）
                               防抖 → System Prompt（角色＋規則＋狀態）→ 最近 3 輪記憶
                               → chatCompletion（shared/ai-fetch.ts，10 秒 AbortController）
          ◀── { ok: true, text } → 對話框逐字打出來
          ◀── { ok: false, reason } → say('click')：角色包 character.json 的台詞池隨機一句
```

V0.20 把 `WhaleAi`、`ChatMemory`（原 `host/ai.ts`）和 `chatCompletion`（原 `host/ai-client.ts`）搬到 `shared/`，
舊路徑保留 re-export，host 的行為完全不變。

> 需求裡說的 `dialogues.json`，在這個專案就是角色包的 **`character.json` 的 `lines`**（依時段、好感、天氣分組的台詞池），
> 降級時從裡面抽一句；換角色包時台詞跟著換。

### 4.3 介面與核心類別（`src/client/ai-browser.ts`）

```ts
interface PlayerAiSettings {          // 給 🔑 設定畫面用；DSH 版沒有
  readonly hasKey: boolean;
  masked(): string;                   // sk-…a1b2
  save(key: string): void;            // 存空白 = 清除
  clear(): void;                      // 連對話記憶一起清
  test(key?: string): Promise<{ ok: true } | { ok: false; message: string }>;
}

class AIChatService implements PlayerAiSettings {
  constructor(file: AiFile, opts?: { store?, fetch?, now?, timeoutMs = 10_000, baseUrl = 'https://api.deepseek.com', model = 'deepseek-chat' });
  chat(req: ChatRequest, defs?): Promise<ChatReply>;   // 不會丟例外
}
// ChatReply = { ok: true, text, source: 'ai' } | { ok: false, reason: 'no_key'|'timeout'|'network'|'http'|'bad_response'|'rate_limited'|… }
```

`chat()` 的步驟：

1. 沒有 Key → `{ ok:false, reason:'no_key' }`（不發請求）
2. 檢查請求附的遊戲狀態快照（`sanitizeSnapshot`：只留固定欄位、限制長度、去掉換行和大括號，防 prompt 注入）
3. `WhaleAi.chat()`：
   - **防抖**：`RateGate(minIntervalMs = 3000, perMinute = 12)`，同一個角色 3 秒內只送第一次，有請求在路上也不送 → `rate_limited`
   - 組 messages：`system` + 最近 `historyTurns = 3` 輪 + 這一輪的觸發句
   - `chatCompletion(..., { max_tokens: 100, temperature: 1.1 })`
   - 回覆整理：去引號、去旁白、截到 60 字（`sanitizeReply`）；成功才寫進記憶（存 `localStorage['whale-pet:ai-memory']`）

畫面端還有一道防抖（`aiGate`，3 秒）和一道最後保險（15 秒沒回就當失敗），兩道都失敗也只是改說內建台詞。

### 4.5 fetch 超時與錯誤（`src/shared/ai-fetch.ts`）

```ts
export async function chatCompletion(cfg, body, fetchImpl = fetch): Promise<ChatApiResult> {
  const ctrl = new AbortController();
  const timer = setTimeout(() => ctrl.abort(), cfg.timeoutMs);          // 單機版 10_000
  try {
    const res = await fetchImpl(`${cfg.baseUrl}/chat/completions`, {
      method: 'POST',
      headers: { 'content-type': 'application/json', authorization: `Bearer ${cfg.apiKey}` },
      body: JSON.stringify({ model: cfg.model, stream: false, ...body }), // deepseek-chat、max_tokens 100
      signal: ctrl.signal,
    });
    if (!res.ok) return { ok: false, reason: 'http', status: res.status };   // 401 Key 錯、402 餘額、429、5xx
    const data = await res.json().catch(() => null);
    const text = data?.choices?.[0]?.message?.content;
    if (typeof text !== 'string' || !text.trim()) return { ok: false, reason: 'bad_response' };
    return { ok: true, text };
  } catch (err) {
    if (ctrl.signal.aborted || err?.name === 'AbortError') return { ok: false, reason: 'timeout' };
    return { ok: false, reason: 'network' };                               // 斷線、CORS 被擋
  } finally {
    clearTimeout(timer);                                                   // 不管成功失敗都清掉計時器
  }
}
```

### 4.6 畫面：等待動畫與對話框（`pixel-stage.ts` 的 `aiSay`）

```ts
async function aiSay(trigger, event, fallback) {
  if (!aiReady() || thinking || away()) return fallback();   // 沒 Key（aiOff）、正在等、她不在 → 直接說內建台詞
  thinking = true;
  pet.idleUntil = Infinity;                                 // 她停下來等
  showThinking(true);                                       // 頭上：「思考中 ●●●」三個點輪流跳
  const text = await aiLine('whale', trigger, event);       // 失敗一律回傳 null（不丟例外）
  showThinking(false);
  thinking = false;
  if (!text) return fallback();                             // say('click')：character.json 台詞池隨機一句
  showLine(text, ch.actions?.onClick);                      // 對話框（立繪＋名字）逐字打出來，配合開心的動作
}
```

- 等待中再點她：`thinking` 擋住，不會重送。
- 回應超過 10 秒：`AbortController` 中止 → `timeout` → 內建台詞；`aiLine` 另外有 15 秒的最後保險。
- 沒有 Key 回傳 `no_key` 後 `aiOff = true`，之後點她不再嘗試；在 🔑 設定存了 Key 就重新打開。
