## 2. 需求一：場景劃分與互動熱區

### 資料結構

熱區沿用 V0.9 的 `interactables.json` 格式：
- 座標用**原圖像素**，直接在繪圖軟體裡量背景圖就好。
- 新增兩種動作 `coin_flip`、`cards`（`src/shared/hotspots.ts` 的 `HotspotAction`）。

```ts
type HotspotAction =
  | { type: 'shop'; shop: string }          // 吧台：點餐（gameplay.json 的 shops.tavern）
  | { type: 'coin_flip' }                   // 街機：猜硬幣（tavern.json 的 coinFlip）
  | { type: 'cards'; npc?: string }         // 牌桌：比大小；沒寫 npc = 讓主人選對手
  | { type: 'eat' } | { type: 'show_dialogue'; lines: string[] } | { type: 'door'; … } | …;

interface HotspotDef {
  id: string; name: string;
  rect: { x; y; w; h };      // 點擊範圍（原圖像素）
  stand?: { x; y };          // 她走到哪裡才觸發
  face?: Facing; pose?: string; emote?: string; hint?: string;
  blocks?: boolean;          // 擋路（預設 true）
  approach?: 'walk' | 'fade' | 'none';
  action: HotspotAction;
}
```

### 觸發偽代碼

點擊判定、走過去、觸發，都是 V0.9 原本的流程，這一版只加了兩個分支：

```
onPointerDown(screenXY):
  p = 螢幕座標 → 原圖座標
  h = hotspotAt(scene, p)                 // 重疊時取面積最小的（小東西疊在大家具上也點得到）
  if h == null: 走到點的那一格; return
  if h.unlock 還沒解鎖: 打開解鎖面板; return
  approach(h):
    walk → 尋路走到 h.stand（找不到路就 fade：黑幕一閃出現在旁邊）
    none → 原地觸發
  到了 → runHotspot(h)

runHotspot(h):
  她面向 h.face，冒 h.emote
  switch h.action.type:
    'shop'      → openShop(h.action.shop)        // 吧台 → 點餐視窗
    'coin_flip' → openCoinFlip()                 // 街機 → 猜硬幣（見第 4 節）
    'cards'     → openCards(h.action.npc)        // 牌桌 → 比大小（見下面）
    'eat'       → 坐下、打開揹包「吃的」分頁
    …
```

### 牌桌：跟 NPC 比大小

**規則**（host 的 `applyAction`，`case 'cards'`）：

```
cards(npc):
  if npc 不在酒館（tavernNpcs(now) 不含它）: return 失敗 'not_here'
  mine   = 1 + floor(rng() * 13)          // A=1 … K=13
  theirs = 1 + floor(rng() * 13)
  outcome = mine > theirs ? win : mine < theirs ? lose : tie
  if outcome == win 而且 今天贏這個人的次數 < cards.maxWinsPerDay:
      npc 好感 += cards.friendship（上限 1000）
  今天贏這個人的次數 += (outcome == win ? 1 : 0)
  return { mine, theirs, outcome, gain, friendship }
```

**畫面狀態機**（`src/client/pixel/ui-tavern.ts`）：

```
pick（選對手；只有一個人時跳過）→ ready →「發牌」→ dealing → host 回結果 → result
result →「再一把」→ dealing
result →「換人」→ pick
```

白天酒館只有老吳；晚上 8 點以後，老陳、阿綱、小葵也可以選。

**數值**（`tavern.json`）：贏一次好感 +15，每個人每天最多算 3 次。

## 3. 需求二：社交時間（Social Hour）

### 資料結構（`packs/whale-girl-pixel/tavern.json`）

```jsonc
{
  "scene": "tavern",
  "residents": [   // 一直在酒館的人
    { "npc": "barkeep", "at": {"x": 660, "y": 352}, "hideBelow": 342, "stand": {"x": 600, "y": 495} }
  ],
  "social": {
    "fromHour": 20, "toHour": 24,        // 本機時間 20:00～24:00；寫 22、2 也可以（跨午夜）
    "seats": [
      { "npc": "fisher",  "at": {"x": 512,  "y": 478}, "activity": "bar",    "bubble": ["收攤之後這杯最好喝！", …] },
      { "npc": "smith",   "at": {"x": 1138, "y": 470}, "activity": "arcade", "bubble": ["這關的魔王好硬。", …] },
      { "npc": "florist", "at": {"x": 1428, "y": 780}, "activity": "cards",  "bubble": ["要不要來玩一把？", …] }
    ],
    "talkRadius": 2,                     // 她走到幾格內會自動聊
    "talks": {
      "smith": [ { "her": "阿綱，你也喜歡這款遊戲嗎？", "reply": "……嗯。下班之後就想打一下。別跟別人說。" }, … ],
      …
    }
  }
}
```

- `at`：NPC 腳的位置（酒館原圖像素）。
- `hideBelow`：這條線以下不畫，用在站在吧台後面的人。
- `stand`：跟他說話時她要站哪裡。
- `bubble`：NPC 頭上偶爾冒出的小對話。

### 偽代碼

**誰在哪裡**：host 和瀏覽器共用 `src/shared/gameplay.ts`。

```
isSocialHour(now):
  h = 本機時間的小時
  return fromHour <= toHour ? (fromHour <= h < toHour) : (h >= fromHour || h < toHour)

tavernNpcs(now) = residents 的 npc ＋ (isSocialHour(now) ? seats 的 npc : [])
```

**地圖上放 NPC**（`pixel-stage.ts` 的 `deriveMap`，酒館裡的人變了就重算）：

```
if 現在的場景 == 酒館:
  for seat in residents ＋ (社交時間 ? seats : []):
    在 seat.at 那一格放一個 kind 'npc' 的互動物件（點了照樣是聊天／送禮／商店）
    那一格設成不能走
else if 社交時間:
  從小鎮（或任何地圖）拿掉 seats 裡的 NPC，那一格變成能走
```

**時間到就搬家**：

```
scheduleSocial():
  下一個整點邊界 = min(下一次 fromHour, 下一次 toHour)
  在那之後 0.5 秒重新拿一次畫面資料 → deriveMap 重算 → NPC 出現在酒館、從小鎮消失
```

**她靠近時的特殊對話**（每一幀檢查一次，`checkSocialTalk`）：

```
checkSocialTalk():
  if 不是社交時間、不在酒館、對話框或視窗開著、她不在家、正在釣魚／思考: return
  if 她正要去做事（有目的地，例如走去點餐）: return      // 路過不打斷，做完、停下來再聊
  me = 主人自己走（P 模式）? 主人的格子 : 她的格子
  for npc in 酒館裡的 NPC:
    if 今晚已經跟他聊過: continue
    if |me - npc| > talkRadius: continue
    記住「今晚聊過 npc」
    她停下來、面向 npc
    對話框：她說 talk.her → 關掉後換 npc 說 talk.reply（用 npc 的頭像）
    return                                                  // 一次只聊一個
```

**NPC 頭上的小對話**：每 7～15 秒，隨機挑一個在酒館、有 `bubble` 的 NPC，冒一句 3.8 秒。

## 4. 需求三：街機猜硬幣

### 規則（host；`gameplay.ts` 的 `case 'coin_flip'`）

```
coin_flip(guess ∈ {heads, tails}):
  if guess 不是正／反: return 失敗 'unknown'
  if 金幣 < cost(10): return 失敗 'no_item'
  result = rng() < 0.5 ? heads : tails                // 亂數狀態存在存檔裡，同樣輸入同樣結果
  win = (result == guess)
  金幣 += win ? (reward − cost) = +10 : −cost = −10   // 一次做完：不會扣了錢沒結果
  if win:
    room = min(maxAffectionPerDay − 今天猜硬幣拿過的好感, 每日好感上限 − 今天拿過的好感)
    好感 += min(affection(2), room)
  return { guess, result, win, coins, gain, levelUp? }
```

**數值**（`tavern.json` 的 `coinFlip`）：

| 項目 | 數值 |
|---|---|
| 一次花費 | 10 金幣 |
| 猜中拿回 | 20 金幣（淨賺 10） |
| 猜中她的好感 | +2 |
| 猜硬幣一天最多拿的好感 | 6 |

### 畫面狀態機（`src/client/pixel/ui-tavern.ts` 的 `FlipState`）

```
 idle ──「投 10 金幣」──▶ choose ──「🐋 正面／🌊 反面」──▶ flipping ──host 回結果──▶ result
   │                                                  │                              │
   └─ 金幣不夠 ──▶ broke                              └─ host 說金幣不夠 ──▶ broke     ├─「再玩一次」──▶ choose
                                                                                     └─「不玩了」──▶ 關掉
```

| 狀態 | 畫面 | 按鈕 |
|---|---|---|
| `idle` | 「主人，玩一次好不好？」 | 投 10 金幣（不夠時灰掉） |
| `choose` | 「硬幣會落在哪一面呢？」 | 🐋 正面、🌊 反面 |
| `flipping` | 硬幣轉（至少 1.2 秒，同時送出 `coin_flip`） | 無 |
| `result` | 是正／反面、金幣 ±、好感 +、她的一句話 | 再玩一次、不玩了 |
| `broke` | 「金幣不夠了…先去賺一點再來玩吧。」 | 好吧 |

```
onGuess(side):
  state = flipping(side); 畫面
  [res] = await all(act({type:'coin_flip', guess: side}), 等 1.2 秒)
  if 視窗已經關了: return                  // 結果已經寫進存檔，不再跳出來
  if 失敗 no_item: state = broke
  else: state = result(res.event), 她冒愛心（猜中）或「…」（沒中）
```

**投幣只是進到選邊的畫面，真正扣錢在 host 那一步**：付錢、擲硬幣、給獎一起算完。所以就算畫面中途關掉、網路斷掉，也不會發生扣了錢卻沒有結果。
