# V0.9 設計書：背景圖房間＋互動熱區（Hotspot）

房間換成一整張精緻的像素背景圖（貝殼床、大水族箱、書桌、沙發區、寶箱…）。圖上的家具能不能點、點了做什麼，**全部寫在 `packs/whale-girl-pixel/interactables.json`**。改位置、加家具、換動作都不用改程式。

---

## 0. 核心想法：一張圖，兩層資料

```
┌──────────────── 原圖 1402×1122（你在繪圖軟體裡看到的座標）────────────────┐
│  熱區 rect：點擊判定、滑鼠高亮、提示文字      ← 用原圖像素，精確到家具邊緣   │
│  地板 floor、障礙 obstacles、站位 stand       ← 也用原圖像素寫                │
└────────────────────────────────────────────────────────────────────────────┘
                     │ 載入時換算（buildBackgroundMap）
                     ▼
┌──────────── 遊戲格子地圖 15×12 格（每格 16px）────────────┐
│  能不能走、尋路、站位、門、作息地點                        │  ← 沿用原本的系統
│  sleep → 原本的床；shop → 原本的商店；door → 原本的門     │
└────────────────────────────────────────────────────────────┘
```

- **點擊和高亮用原圖像素**：可以點得很準，不會因為格子太粗而點到旁邊的家具。
- **走路用格子**：原本的 A*／BFS 尋路、站位、擺家具、作息全部照用，不用重寫。
- 原圖 1402×1122 的寬高比是 1.25，換算成 15×12 格（240×192）剛好一樣，放在 20×12 的畫面中間，左右留黑邊。
- 背景圖會先依目前的放大倍率，用高品質縮圖縮一次存起來，之後每一幀直接貼上。所以原圖的細節會保留到螢幕解析度，不會被縮成 16px 格子那麼糊。

### 欄位

| 欄位 | 必填 | 說明 |
|---|---|---|
| `id`、`name` | ✓ | id 不能重複 |
| `rect` | ✓ | 點擊判定範圍（原圖像素）。重疊時取**面積小的**，所以床上的枕頭可以單獨點 |
| `action` | ✓ | 見下表 |
| `stand` | | 她站哪裡（原圖像素，腳的位置）。沒寫就找範圍旁邊最近能站的格子；量歪了（落在家具上）會自動挪到最近能走的格子 |
| `face` | | 觸發時面向：`up`／`down`／`left`／`right` |
| `pose` | | 觸發時的動作（`character.json` 的 clips：`sit`、`sleepy`、`happy`…） |
| `emote` | | 頭上冒的表情（`heart`、`note`、`zzz`…） |
| `hint` | | 滑鼠提示；沒寫用 `name` |
| `blocks` | | 擋不擋路，預設 `true`。門、地毯、吊燈寫 `false` |
| `unlock` | | 要先解鎖（`gameplay.json` 的 unlocks）。沒解鎖時高亮是灰紫色、提示加 🔒，點了開解鎖視窗 |
| `approach` | | `walk`（預設，走過去）、`fade`（黑幕一閃直接出現）、`none`（原地觸發） |

### 動作類型（`action.type`）

| type | 參數 | 做什麼 | 沿用 |
|---|---|---|---|
| `sleep` | — | 打開睡覺視窗 → 快轉到隔天早上 6 點、體力補滿 | 原本的床 |
| `eat` | — | 坐下（`pose`）＋打開揹包的「吃的」分頁 → 選食物按「餵她吃」→ 恢復飽食、體力、好感 | V0.7 的 feed |
| `open_ui` | `ui`: `bag`／`codex`／`pets`／`worldmap`／`gifts`，`tab`（揹包分頁） | 打開那個介面 | 側邊欄、Modal |
| `show_dialogue` | `lines`: 字串陣列 | 從 lines 隨機抽一句，用 RPG 對話框逐字顯示 | `showLine` |
| `shop` | `shop`: 商店 id | 打開商店視窗（書桌 = 料理台） | 原本的商店 |
| `door` | `to`、`spawn` | 走到門口 → 換場景 | 原本的門 |

## 2. 點擊判定

```ts
// 滑鼠 → 遊戲地圖像素（原本就有）
const { lx, ly } = toMap(event);

// 遊戲地圖像素 → 原圖像素
const c = imgToMap(bg, TS);                 // sx = 15*16/1402, sy = 12*16/1122
const p = { x: lx / c.sx, y: ly / c.sy };

// 找熱區：點在 rect 裡；重疊取面積最小
function hotspotAt(bg, p) {
  let best = null;
  for (const h of bg.hotspots) {
    if (p.x < h.rect.x || p.y < h.rect.y || p.x >= h.rect.x + h.rect.w || p.y >= h.rect.y + h.rect.h) continue;
    if (!best || area(h.rect) < area(best.rect)) best = h;
  }
  return best;
}

// 背景圖場景的點擊順序
function onPointerDown(e) {
  if (busy || 對話框開著) return;
  if (點到寵物) return 寵物互動();
  if (點到她) return talk();                 // 她站在水族箱前時，點她的頭是跟她說話，不是開圖鑑
  const hs = hotspotHit(lx, ly);
  if (hs?.door) return clickDoor(hs.door);  // 鎖著 → 解鎖視窗；她不在 → 主人直接過去；不然走到門口
  if (hs?.it)   return approach(hs.it);     // 走過去 → interact()
  if (地板能走) walkTo(格子);                // 點空地：走過去
}
```

## 3. 視覺反饋（滑鼠移上去）

```ts
function onPointerMove(e) {
  const hs = busy ? null : hotspotHit(lx, ly);
  hoverHs = hs ? { rect: hs.rect, locked: hs.locked } : null;     // 給畫面用
  canvas.style.cursor = hs || 點到她 ? 'pointer' : 'default';      // 小手
  if (hs) 顯示提示(hs.hint, 在熱區上方置中);                          // 「🐠 水族箱：看魚類圖鑑」
  else    隱藏提示();
}
onPointerLeave = () => { hoverHs = null; 隱藏提示(); };

// 每一幀最後畫（在時段濾色之後，晚上也看得清楚）
function drawHotspotHover(now) {
  if (!hoverHs || busy || 對話框開著) return;
  const k = 0.55 + 0.25 * sin(now / 260);           // 一閃一閃
  fill(roundRect(hoverHs.rect, 3), locked ? 灰紫 : 暖白, 透明度 0.16*k);
  stroke(roundRect(hoverHs.rect, 3), locked ? 灰紫 : 淡金, 透明度 k);
}
```

用矩形高亮，不用描家具外框：

- 不用另外準備每件家具的遮罩圖或描邊圖。
- 換背景圖時只要重量一次 rect。
- 如果之後想要「家具本身發亮」，可以在熱區加一個 `mask` 欄位，指向那件家具的去背小圖，高亮時把那張圖用 `globalCompositeOperation = 'lighter'` 疊上去。（目前沒做）

## 4. 互動邏輯

```ts
async function interact(target) {               // 走到站位後呼叫
  if (鎖著) return 解鎖視窗();
  switch (target.kind) {
    case 'bed':     stop(面向); openSleep(); break;    // ← 熱區 sleep
    case 'shop':    openShop(target); break;            // ← 熱區 shop
    case 'hotspot': runHotspot(target); break;          // ← 其他熱區
    …原本的釣魚、農田、機器…
  }
}

function runHotspot(it) {
  const h = it.hotspot, a = h.action;
  if (她在) { stop(h.face); if (h.emote) showEmote(h.emote); }

  // 擺姿勢（坐下）：介面開著就一直坐著；吃東西時的開心反應演完、說完話，會再坐回去；介面關掉才起身
  const pose = () => {
    if (!她在 || !h.pose || !playClip(h.pose)) return undefined;
    pet.idleUntil = Infinity; seatedPose = h.pose;
    return () => { seatedPose = null; idle(700); };   // 當成介面的 onClose
  };

  switch (a.type) {
    case 'open_ui':
      if (a.ui === 'bag')   { if (a.tab) bagTab = a.tab; showPanel('bag', renderBag, pose()); }
      if (a.ui === 'codex') showPanel('codex', renderCodex, pose());
      …pets / worldmap / gifts
      break;
    case 'eat':                                   // 沙發几
      bagTab = 'food';                            // 揹包新分頁「吃的」：只列能吃的（item.food）
      showPanel('bag', renderBag, pose());        // 坐下＋打開揹包
      if (揹包沒有能吃的) toast('揹包裡沒有能吃的東西：去釣魚或收成吧！');
      break;                                      // 選食物 →「🍴 餵她吃」→ act({type:'feed'}) → 飽食、體力、好感上升
    case 'show_dialogue':
      她在 ? showLine(pick(a.lines), h.pose) : toast(`${h.name}：${pick(a.lines)}`);
      break;
  }
}
```

|---|---|
| 貝殼床 | 走到床尾 → 睡覺視窗 → 快轉到隔天 6 點，體力補滿（V0.5 的睡覺） |
| 沙發几 | 走到沙發旁 → **坐下**＋揹包「吃的」分頁 → 餵她（飽食＋25、體力＋13、好感＋3，以鱸魚為例）→ 關揹包才起身 |

| 書桌 | 走到椅子後面 → 料理台（做料理） |
| 寶箱 | 走過去 → 揹包 |
| 窗戶、瓶中船 | 走過去 → 說一句話 |
| 水母燈 | 原地說一句話（`approach: none`） |

## 5. 尋路：走過去，還是淡入淡出？

**預設走過去**，遠的家具也一樣。走不到時自動改成淡入淡出。也可以在 JSON 指定：

```ts
function approach(target) {
  if (她不在) return interact(target);                    // 主人自己操作
  if (reachedTarget(pet.tile, target)) return interact(target);
  const how = target.hotspot?.approach ?? 'walk';
  if (how === 'none') return interact(target);            // 吊燈：原地觸發
  const dist = distances(map, pet.tile);                  // BFS：從她到每一格的步數
  const best = target.stands.filter(走得到).sort(近的先)[0];
  if (how === 'fade' || (!best && target.stands.length)) return blinkTo(target.stands[0], target);
  if (!best) return showEmote('dots');
  walkTo(best, { kind: 'interact', target });             // A* 走過去；到了 → interact()
}

// 到了沒：有指定站位 → 要站在那一格；沒有 → 緊貼家具就算
function reachedTarget(t, it) {
  return it.standFixed ? it.stands.some(s => s.x === t.x && s.y === t.y) : isNear(t, it.rect);
}

// 淡入淡出：黑幕 → 瞬移到站位、面向家具 → 掀開 → 觸發
async function blinkTo(tile, target) {
  busy = true;
  fade.on();  await wait(FADE_MS);
  placeAt(tile, target.hotspot.face);
  fade.off(); busy = false;
  interact(target);
}
```

**簡單版尋路（BFS）的偽代碼**，專案裡實際用的是 `src/shared/path.ts` 的 A*：

```
queue ← [起點]；came_from[起點] ← 無
當 queue 不空：
  cur ← queue 取出最前面
  如果 cur 是終點：沿著 came_from 倒推回起點，反轉 → 路徑
  對 cur 的上下左右四格 n：
    如果 n 在地圖裡、能走、還沒走過：came_from[n] ← cur，n 放進 queue 最後
找不到 → 回傳空（改用淡入淡出）
```

**怎麼選**：

| | 走過去（walk） | 淡入淡出（fade） |
|---|---|---|
| 感覺 | 像真的住在房間裡，有生活感 | 快、乾脆 |
| 適合 | 房間這種一兩秒走得到的地方 | 很遠、或路線很繞的家具；路被擺的家具擋住時（自動） |
| 代價 | 要等她走 | 有一點跳 |

房間目前全部用走的：她每秒走 2.5 格，房間裡大多 1～3 秒就到，從左下角走到右邊最遠約 5 秒。覺得太慢，把那個熱區改成 `"approach": "fade"` 就好。

## 6. 怎麼量座標、加一件新家具

1. 用任何繪圖軟體（小畫家也行）打開 `assets/source/whale-room.jpg`，滑鼠移到家具左上角，看左下角顯示的座標，再量寬高。
2. 在 `hotspots` 加一筆：`id`、`name`、`rect`、`action`；需要的話加 `stand`（她站的地方，量地板上的一點）。
3. 跑 `npx tsx scripts/check-pixel.ts`，它會檢查：
   - 範圍有沒有超出原圖、id 有沒有重複、動作和參數寫得對不對；
   - 站位走不走得到、門口有沒有能站的格子；
   - `tiles` 寬高比跟原圖差太多時，會提醒圖會被拉扁。
4. 重新整理畫面，滑鼠移過去看高亮框準不準。

**換一張新的房間圖**：

1. 圖放在 `assets/rooms/`，改 `image`、`imageSize`。
2. `tiles` 要配合寬高比（例如 16:9 的圖用 20×12 剛好填滿畫面）。
3. 重量 `floor` 和熱區。

**其他場景也能用**：在 `scenes` 下加一個場景 id，例如 `"attic": { … }`，那個場景就會改成背景圖模式。

## 7. 限制

- 背景圖房間沒有圖塊，所以**換地板、換壁紙**的道具在這裡不能用，會提示「這個房間是一整張畫好的背景圖」。閣樓還可以換。**擺家具**（泰迪熊之類）照樣可以。
- 她會畫在所有家具前面（背景圖只有一層）。她走不進家具的範圍，所以平常看不出來；如果之後要做「走到床後面被擋住」，需要另外切一張前景圖。
- `tiles` 是 15×12，畫面兩側各有 2.5 格黑邊（原圖本身就是 1.25:1）。
