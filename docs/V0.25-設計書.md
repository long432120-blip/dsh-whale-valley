# V0.25 設計書：點側欄 → 遊戲在獨立視窗（不再蓋住 DSH）

- 版本：`0.25.0`（套件檔 `release/dsh-whale-valley-0.25.0.tgz`）
- 只改「怎麼開遊戲」和 DSH 那張卡片；**玩法、存檔、host 的橋接通道都沒有改**
- 單機試玩版（`demo/pixel-standalone.html`）不受影響

## 1. 為什麼 V0.23／V0.24 的「開新視窗」在桌面版沒反應

V0.24 的卡片有兩顆按鈕：`▶ 啟動遊戲`（全螢幕圖層）和 `🪟 開新視窗玩`（`window.open`）。第二顆在 DSH 桌面版**按了不會有反應**，原因在 Electron 主程序（`app.asar` → `lib/main.js`）：

```js
view.webContents.setWindowOpenHandler(({ url }) => {
  const destination = new URL(url);
  if (destination.protocol === 'https:' && !destination.username && !destination.password)
    shell.openExternal(url).catch(() => {});   // 只有 https: 會丟給系統瀏覽器
  return { action: 'deny' };                   // 其他一律拒絕
});
```

我們的遊戲頁是 `http://127.0.0.1:<port>/api/dsh-whale-valley/play`（`http:`、又是本機），所以直接被 deny：

- `window.open(...)` 拿到的是 `null`（或被靜默丟掉）
- 不會開視窗、也不會有錯誤訊息，看起來就像按鈕壞了

全螢幕那顆（模式 A）可以用，但它會蓋住整個 DSH——擁有者要的正是「不要蓋住」。

## 2. 現在的做法：host 用系統瀏覽器開「應用程式模式」視窗

```
點左側欄「鯨魚谷物語」
   → main 面板掛起來（卡片顯示狀態）
   → POST /api/dsh-whale-valley/open-window
        → 最近 40 秒內有遊戲畫面在呼叫通道？ → 回 {alreadyOpen:true}，不重開
        → 找 Chrome／Edge 的執行檔
        → spawn("<chrome>", ["--app=http://127.0.0.1:<port>/api/dsh-whale-valley/play",
                             "--window-size=1280,900", ...])，detached + unref
        → 回 {ok:true, mode:"app", browser:"Chrome"}
   → 卡片顯示「🪟 已用 Chrome 開了獨立視窗」
```

`--app=` 是 Chromium 的應用程式模式：**沒有網址列、沒有分頁列、沒有書籤列**，1280×900 一個乾淨的視窗，看起來就是一個獨立的小程式；關掉視窗＝結束遊戲。

找不到 Chrome／Edge 時退回系統預設瀏覽器（`cmd /c start`、macOS `open`、Linux `xdg-open`，一般瀏覽器視窗）。

### 為什麼不需要 DSH 的登入 cookie

`/api/dsh-whale-valley/*` 是插件自己用 `ctx.webServer.register({kind:'prefix'})` 掛的路由，不是 DSH 的 index。實測：**完全不帶 cookie** 直接 GET `/api/dsh-whale-valley/play` → `200 text/html`。所以系統瀏覽器（另一個 process、沒有 DSH 的 cookie）也能玩，存檔照樣走 host 的 `POST /api/dsh-whale-valley/<方法>`。

### 不重複開視窗

每個遊戲畫面每 30 秒會打一次 host 通道（`visit`／`getView`），host 記下 `lastClientAt`：

- 卡片自動開（點側欄那一下）→ 不強制：40 秒內有通話就當「視窗還開著」，只顯示「🪟 遊戲視窗已經開著」
- 按卡片上的按鈕 → `force: true`：不管怎樣都再開一個（視窗真的被關掉、或想開第二個的時候用）
- 點側欄的**當下**在同一次使用者點擊裡，所以 `window.open` 以外的路徑也不會被瀏覽器攔

## 3. 改了哪些檔案

| 檔案 | 改動 |
|---|---|
| `src/host/open-window.ts`（新） | `launchGameWindow(url)`：找 Chrome／Edge，`--app=` 開視窗；找不到退回系統預設瀏覽器；`spawn` 一律 `detached`＋`unref`，錯誤只寫 log |
| `src/host/index.ts` | 新路由 `POST /api/dsh-whale-valley/open-window`（body `{force?:boolean}`）；`lastClientAt` 記「最近一次遊戲通道呼叫」；`apply()` 時記下 `webServer.getOrigin()` 當對外位址（不信任瀏覽器送來的 Host） |
| `src/client/launcher.ts` | `LauncherOptions.mode: 'both'｜'window'｜'fullscreen'`、`autoOpen`、`openWindow?(): WindowOpenResult`（自訂開窗方法）；`LauncherHandle.openWindow()` 改成 `Promise<boolean>` |
| `src/client/dsh-entry.tsx` | 面板改成 `mode:'window'`＋`autoOpen`；`openStandaloneWindow()` 打 host 的 `open-window`，失敗才退回 `window.open`（純瀏覽器部署用）；`createWindowOpener()` 讓第一次不強制、之後按按鈕強制 |
| `locales/zh-TW.json`、`zh-CN.json` | 新 key：`launch.label`（V0.24）、`launch.subWindow`、`launch.openWindow`、`launch.windowOpened`、`launch.windowOpenedBrowser`、`launch.windowOpen`、`launch.windowFailed` |
| `package.json` | `0.24.0` → `0.25.0` |

沒有改：`src/shared/**`、`packs/**`、存檔格式、`whale_pet_*` 工具。

## 4. 實機驗收（2026-11-12，desktop profile，DSH 桌面版）

| # | 檢查 | 結果 |
|---|---|---|
| 1 | `POST /open-window {force:true}` | `200 {"ok":true,"mode":"app","browser":"Chrome"}` |
| 2 | 視窗真的出現 | Chrome 在回呼後 1 秒內開了新的 renderer process（`Win32_Process` 時間對得上） |
| 3 | 那個視窗裡的遊戲有在跑 | 7 秒後再打一次（`force:false`）→ `{"ok":true,"alreadyOpen":true}`，代表遊戲畫面已經在呼叫 host 通道（`visit`／`getView`） |
| 4 | 點左側欄的實際流程 | 面板掛載 → `POST /open-window`（200）→ 卡片顯示「🪟 遊戲視窗已經開著」（視窗本來就開著），**DSH 畫面沒有任何圖層** |
| 5 | 卡片樣式 | 標題「🐋 鯨魚谷物語」、副標「遊戲會在另一個視窗打開，不會擋住 DSH」、按鈕「🪟 打開遊戲視窗」 |
| 6 | `tsc --noEmit`、221 個測試、`check-pixel`、`check:offline`、`check:secrets`、`build` | 全過 |

沒驗到的：`--app` 找不到瀏覽器時的退回路徑（這台有 Chrome）、macOS／Linux 分支、以及按按鈕強制開第二個視窗（會多開一個視窗，不想在驗收時留垃圾）。
