# V0.21 設計書：開源前最終審查

第一次開源前做的四件事：清掉密鑰與個資、強化存檔、清掉測試代碼、寫好 README 和發布指引。
這一版沒有新玩法。

## 1. API Key 與敏感資訊

### 掃描結果

| 項目 | 結果 |
|---|---|
| 寫死的 API Key（`sk-…`） | **沒有**。（V0.22 起測試檔也不放任何像 Key 的字串：需要 `sk-` 格式的測試在執行時才拼出來，其他測試用 `test-key-…`） |
| GitHub／AWS／Google／Slack Token、私鑰 | 沒有。`lib/client.js` 裡看起來像 `ghp…`、`AKIA…` 的字串都是內嵌圖片的 base64，不是 Token |
| 個人 email | 沒有（git 作者用 GitHub 的 noreply 信箱） |
| 本機路徑 | 沒有（V0.20 已經把 Windows 使用者名稱換成 `%USERPROFILE%`） |
| `.env` | 不在 repo 裡；`.gitignore` 擋 `.env`、`.env.*`（只放行 `.env.example`） |
| 大模型的測試請求 | 自動測試全部用假的 fetch／`page.route`，不會真的連網；`npm run demo:ai` 只在使用者自己有 `.env` 時才會呼叫，伺服器只聽 `127.0.0.1` |

### Key 只會從這三個地方來

1. **單機版**：玩家在 🔑 設定自己填，存在自己瀏覽器的 localStorage，只送到 `api.deepseek.com`
2. **DSH 插件**：DSH 內建模型，或 host 讀 DSH 設定 `ai.apiKey` → 環境變數 `DEEPSEEK_API_KEY` → `.env`；瀏覽器拿不到
3. **開發**：`npm run demo:ai` 讀專案根目錄的 `.env`

三條路沒有 Key、逾時（10 秒）、HTTP 錯誤，全部降級成角色包的內建台詞（`character.json` 的 `lines`）。

### 新增：`npm run check:secrets`（`scripts/check-secrets.mjs`）

發布前的檢查腳本，以後每次推送前跑一次：

```
有 git → 只看 git 會提交的檔案（git ls-files -co --exclude-standard）
沒 git → 掃整個資料夾（略過 node_modules、.git、release、assets/source）
對每個文字檔：
  先把 data:…;base64,… 拿掉（避免把圖片誤判成 Token）
  找 sk-… Key（含 test、fake、example、xxxx 的假 Key 不算）、GitHub／Slack／AWS／Google Token、私鑰、
     個人 email（gmail、qq、163、outlook…；noreply 不算）、本機使用者路徑（`C:\Users\<名字>`、`/Users/<名字>/`、`/home/<名字>/`）
  檔名是 .env、.env.local… → 直接算問題
有問題 → 列出「檔案:行號 [類型] 遮罩後的內容」，以代碼 1 結束
```

## 2. 存檔系統

### 原本就有的

- **版本號**：`PetSave.version`（目前是 2；讀到 1 會自動升級）
- **自動存檔**：每個動作當下就存。單機版 `LocalBridge` 每次 `visit／getView／setScene／poke／act` 都寫回 localStorage；
  DSH 版 `JsonStore.update()` 每次都寫檔（先寫暫存檔再改名，不會寫一半）。
  所以睡覺、換地圖、買賣、釣魚、種田…都是做完就存好；畫面開著時每 10 秒結算時間也會存一次。
- **DSH 版壞檔**：`JsonStore.read()` 讀到壞掉的 JSON，先改名成 `save.json.corrupt-<時間>` 再當作新遊戲

### V0.21 補強

#### 單機版讀檔（`src/client/bridge-local.ts`）

```ts
load(now) {
  text = localStorage[key]
  if (沒有存檔) return 新遊戲
  try { raw = JSON.parse(text) } catch { raw = undefined }
  if (!isKnownSave(raw)) {           // 不是物件、是陣列、沒有版本號、版本號不認得（例如更新版本的存檔）
    backup(text)                      // 原始內容 → <key>:backup、時間 → <key>:backup-at
    return 新遊戲
  }
  try { return migrate(raw) }         // 逐欄位檢查，壞掉的補預設值
  catch { backup(text); return 新遊戲 } // 萬一規則還是丟例外
}
backup() → 設定一次性提醒「存檔讀不出來，已經先備份起來，幫你開了新的遊戲」
takeNotice() → 畫面拿到後用 toast 顯示 8 秒（HostBridge 新增選用的 takeNotice）
```

- 「🗑 重新開始」（原本叫重置存檔）要先按確認，而且刪掉前一樣先備份到 `<key>:backup`
- 備份只留最新一份；之後要做「從備份還原」只要讀這個 key

#### 啟動失敗不白畫面（`demo/ui.ts` 的 `showFatal`）

啟動時任何例外 → 在遊戲區塊顯示「🐋 遊戲打不開…」說明、錯誤訊息、「🔄 重新整理」「🗑 備份存檔後重新開始」兩個按鈕。
（瀏覽器停用 localStorage 時遊戲照樣能玩，只是不會存檔。）

#### 防手改（`normalizeGame`）

單機版的存檔在玩家自己的瀏覽器裡，**擋不住**真的想改的人（純前端遊戲都一樣）；
這裡做的是「改壞了也不會讓遊戲出錯、數字不會爆掉」：

| 欄位 | 規則 |
|---|---|
| 揹包 | 只留 `gameplay` 認得的物品（金幣另外處理）；數量取整數；金幣上限 `MAX_COINS` 99,999,999，其他物品上限 `MAX_STACK` 9,999；字串、負數、NaN 丟掉 |
| 好感 | 取整數，0～`MAX_AFFECTION` 99,999 |
| 時間偏移 `clockOffset` | 0～10 年（手改成超大數字會讓日期算不出來） |
| 體力、飽食 | 原本就會夾在 0～上限 |

DSH 版的存檔在 host，瀏覽器只能送「動作」，規則由 host 判斷，本來就改不了。

#### 模糊測試找到並修好的當機

隨機弄壞存檔後睡覺，`seasonAt()` 在時間偏移是超大數字時算出 `NaN`，`writeDiary` 讀不到季節名稱而當掉。
修法：`clockOffset` 設上限；`seasonAt()` 遇到不是有限數字的日期回傳 `null`，索引改成永遠非負。

### 測試（`test/save-recovery.test.ts`，11 項）

- 沒有存檔 → 新遊戲、存檔帶版本號
- JSON 壞掉／不是物件／陣列／版本 99／沒有版本號 → 照樣能玩、原始內容備份、只提醒一次
- 正常存檔不備份；換場景後存檔立刻更新；重新開始先備份
- 手改數值被修正（金幣、物品、好感）
- 模糊測試：隨機弄壞存檔 1,500 次，`migrate → tick → toView → visit → act` 都不丟例外（另外用 5 個種子各跑 6,000 次也通過）
